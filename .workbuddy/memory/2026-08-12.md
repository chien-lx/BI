## 修复导出压缩与顶部导航栏间隙

- **问题 1：数据门户图片导出后页面宽度被压缩**
  - 原因：`html-to-image` 的 `toPng` 在转换过程中会临时修改目标 DOM 的尺寸/定位样式，若直接对当前内容区导出，可能破坏原页面布局。
  - 修复：`PortalPage.tsx` 的 `handleExportImage` 改为先克隆内容节点到视口外（`position: fixed; top/left: -9999px`），并显式设置克隆节点宽度为原节点实际像素宽度，完成截图后再移除克隆节点；原页面完全不受影响。
- **问题 2：顶部导航栏存在间隙，租户切换/账号退出未吸附顶部**
  - 原因：`body` 默认存在 margin，且 Layout 根容器未强制占满视口。
  - 修复：
    - `style.css` 新增全局重置 `html, body, #root { margin: 0; padding: 0; height: 100%; overflow: hidden; }`。
    - `Layout.tsx` 根容器由 `height: 100vh` 改为 `position: fixed; inset: 0`，确保导航栏紧贴视口顶部，无间隙。
- typecheck 通过（无本次修改相关错误）。

## 进一步修复图片导出后页面宽度压缩

- **问题复现**：点击「图片导出」后，数据门户右侧内容区宽度被压缩，图表右侧出现大片空白。
- **根因排查**：
  - `contentRef` 同时被 ContentRenderer 外层 div 和各类型内容子组件（ChartContent/ReportContent/...）的根 div 复用，React ref 最终指向子组件根 div，导出逻辑直接操作子组件 DOM，容易触发重渲染/ResizeObserver 异常。
  - `html-to-image` 直接对当前 DOM 节点导出时，会临时把克隆节点挂到 body，可能干扰当前页面布局。
- **修复措施**：
  - `PortalPage.tsx`：移除所有子组件的 `innerRef` prop，`contentRef` 仅挂在 ContentRenderer 的外层内容容器上；导出时克隆该外层容器，得到包含标题、卡片、图表的完整内容区图片。
  - 导出流程改为先把克隆节点放入一个尺寸明确、位于视口外的独立 `container` 中，完成 `toPng` 后再整体移除 container，彻底隔离对原页面布局的影响。
  - 给内容容器及右侧 flex 区域显式增加 `width: 100%` 和 `minWidth: 0`，避免 flex item 在导出过程中被压缩。
- typecheck 通过（剩余报错仍为 DataExplorePage/dataset/report 既有问题，与本次无关）。

## 个人工作台 → 数据门户「选中态跳转」

- **需求**：在个人工作台点「去门户查看 / 去查看」后，打开的数据门户应**默认选中该内容并直接渲染**（左侧目录树高亮该项、右侧内容区加载），效果与门户内手动点击资产一致。
- **实现**：
  - 发起方 `PersonalWorkbenchPage.tsx`：两处按钮（收藏卡片「去门户查看」、最近浏览「去查看」）写入 `window.location.hash = 'page=portal&assetType=<type>&assetId=<id>'`；最近浏览项因仅有 type/name 无 id，先用 `allAssets.find(a => a.type===r.assetType && a.name===r.assetName)` 反查到含 id 的资产再跳转（找不到则只跳 `page=portal`）。
  - 目标方 `PortalPage.tsx`：
    - 修正 import 路径（`../../common/useHashPage` → `../../../common/useHashPage`，因文件在 `pages/` 三层深）。
    - 新增 `findAssetById(type, id)` 辅助函数，按类型从 charts/reports/dashboards/dataScreens 反查 `{id,name,type}`。
    - 把 `activeTab` 状态从 `DirectoryTree` 提升到 `PortalPage`，`DirectoryTree` 改为接收 `activeTab`/`onActiveTabChange`（页签切换与列表高亮分别由 `activeTab`/`selectedId` 驱动）。
    - 主组件 `useEffect([])` 解析 `parseHashParams(window.location.hash)` 的 `assetType`/`assetId`，命中则 `setSelected(asset)` + `setActiveTab(assetType)`，实现挂载即恢复选中态。
