## 修复：左侧「登录」菜单点击无效
- 现象：Make 目录树已显示「登录」节点，但点击后仍停留在个人工作台，没有切换到登录页。
- 真因：
  1. `Layout.tsx` 的导航组里根本没有渲染「登录」节点（目录树是 Make 框架从 `defineHashPageRoute` 生成的，和 Layout 自定义导航不同步）。
  2. 即使用户通过某种方式切到 `login`，`AppShell` 里的 `useEffect` 会在登录状态下自动把 `#page=login` 跳回 `personal-workbench`。
  3. `AuthContext.logout()` 直接 `window.location.reload()`，无法配合 React 状态做平滑切换。
- 修复：
  1. `Layout.tsx`：导入 `LogIn`；`PageId` 增加 `'login'`；在 `allNavGroups` 最前加「系统入口」组，放入 `{id:'login', label:'登录', icon: LogIn}`。
  2. `AuthContext.tsx`：`logout` 不再 `reload`，改为 `setLoggedIn(false) + 清理 localStorage`。
  3. `index.tsx`：`pageMap` 注册 `login: LoginPage`；`AppShell` 取到 `logout`；包装 `handleNavigate`：目标是 `login` 且已登录时，先 `logout()` 再 `setPage('login')`；未登录时本来就会渲染 `LoginPage`。
  4. `LoginPage.tsx`：`onLoginSuccess` 改为可选，避免 `pageMap` 类型报错。
  5. 重新运行 `scripts/sync-project-metadata.mjs` 同步目录树。
- 结果：已登录状态下点击「登录」会退出并显示登录页；重新登录后自动进入个人工作台。Vite HMR 正常，53817 入口可访问。

## 排查：改了多文件后"点击没反应 / 假死"（HMR 残留）
- 现象：改了 `index.tsx`(AppShell/handleNavigate)、`AuthContext.tsx`(logout 不再 reload)、`Layout.tsx`(加登录节点) 后，浏览器里「登录」节点出现了，但点击无效，仍停在工作台。
- 真因：Vite HMR + React Fast Refresh 是**按模块边界热更**，当同时改了 Provider / 根组件 / 子组件时，子组件（Layout）热更生效（看到新节点），但 AppShell / AuthContext 闭包仍是旧逻辑；旧的 `useEffect(loggedIn && page==='login' → 跳回工作台)` 把路由又弹回，表现为"点击假死"。
- 排查手段：用 `curl http://localhost:51720/<path>` 和 `curl http://localhost:53817/<path>` 比对 served 模块是否含新符号（如 `handleNavigate`），确认**服务端代码已是最新** → 问题在浏览器侧 HMR 状态残留。
- 解决：`kill` 掉 51720 的 vite 子进程（PID 用 `lsof -i :51720 | grep LISTEN` 找），再 `env -u NODE_OPTIONS <node> node_modules/vite/bin/vite.js --port 51720 --strictPort` 后台重启（make 53817 会复用，不起双实例）；浏览器刷新即加载干净模块。
  - node 路径：`/Users/study/.workbuddy/binaries/node/versions/22.22.2/bin/node`（必须 `env -u NODE_OPTIONS`，否则当前 shell 的 NODE_OPTIONS 带 `--use-system-ca` 被 node 拒绝）。
- 经验：**一处表现型 bug（点击无效/样式不动/假死）但 served 代码已含新逻辑时，优先怀疑 HMR 残留，直接重启 51720 客户端运行时 + 硬刷新**，比反复改代码高效。
