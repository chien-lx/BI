## Axhub 原型预览架构 & 资源加载错误排查（重要）

- 平台自带两套服务，不要手动 `npm run dev`（会起第三个冗余实例，且会与平台 runtime 抢写 `.axhub/make/.dev-server-info.json` 造成不稳定）：
  - **53817 = admin 宿主**（PID 5204，`node .../bin/make` 衍生）：负责提供 host 级资源 `/assets/dev-template-bootstrap.js`。
  - **51720 = runtime dev server**（PID 5231）：真正渲染原型页面；用户预览地址即 `http://localhost:51720/prototypes/<name>?agentToolbar=host`。
- bootstrap 注入逻辑（`vite-plugins/clientPreviewPlugin.ts` 的 `resolveAdminServerOrigin`）会把 `<script data-axhub-dev-template-bootstrap src="http://localhost:53817/assets/dev-template-bootstrap.js">` 注入到 51720 的页面——**origin 指向 53817(admin) 是正确的**，该文件由 admin 提供。
- 报 `资源加载失败: http://localhost:53817/assets/dev-template-bootstrap.js` 通常是 admin 宿主那一瞬间的瞬时不可达；资源本身正常时连续请求均 `HTTP 200`。排查顺序：① 确认 53817 在监听（`lsof -iTCP:53817`）；② `curl -I 53817/assets/dev-template-bootstrap.js` 看是否 200；③ 确认平台 51720/53817 都在、无冗余 dev server 抢端口/抢写 info 文件。
- 本次发现并停掉了之前手动起的冗余 dev server（原占 51721），环境恢复为 53817(admin)+51720(runtime) 双服务、单写者状态。
