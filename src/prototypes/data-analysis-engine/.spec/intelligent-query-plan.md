# 智能问数（NL2SQL）方案梳理

> 目标：为报表、仪表盘、数据大屏提供「自然语言问数」能力，沉淀行业黑话/语义层，并记录用户提问与回答用于持续优化。
> 状态：方案已确认并进入原型设计（2026-08-20 已完成首版原型）

---

## 一、竞品调研结论

### Quick BI（智能小 Q）
- **问数对象 = 数据集**：自然语言直接向 Quick BI 数据集提问，无需写 SQL；未指定数据集时「自动智能选表」（从用户有权限的数据集里匹配最合适的表）。
- **实时输出**：推理过程 + SQL + 图表 + 分析结论。
- **语义层/行业黑话**：通过「企业知识库」定义逻辑、排除干扰、定义专业术语（行业黑话）；某客户导入知识库后准确率 65% → 92%。
- **与页面融合**：小 Q 解读「深度对接仪表板」，在仪表板内直接触发，无需切换界面；可对接 DeepSeek / Qwen / Kimi 等模型。

### 腾讯云 BI（ChatBI）
- **架构链路**：意图识别层 → 检索知识 → 模型关联 → NL2SQL / NL2DSL 双能力（基于混元模型）。
- **统一语义层（Unity Semantics / 本体建模）**：标准化实体、指标、维度、业务逻辑，消除口径歧义、避免 SQL 幻觉。**无语义层准确率 60~70%，完整语义层 90%+**。
- **行业黑话 = 语义层中的同义词/术语映射**；支持多轮对话、输入联想、追问。
- **权限**：OBO 真实用户身份强绑定，复用底层数据平台行级权限，高危 SQL 拦截。

### 通用 NL2SQL 链路（行业共识）
```
用户提问 → 意图识别/黑话改写 → Schema Linking(选表选列) → 生成 SQL/DSL
        → SQL 安全校验(只读 SELECT + 行级权限注入) → 执行 → 结果解释 + 自动可视化
```
- 语义层（Semantic Layer）= 业务术语↔物理字段映射 + 指标口径定义，是准确率的命门。
- 图表自动选择：趋势→折线、占比→饼/环、排名对比→柱状、地图维→地图、相关性→散点、单值→指标卡。
- 安全底线：只读账户 + 后端 Guard 校验 + 行级权限条件注入。

## 三、逐条回答你的疑问

### 1. 训练底层数据集，还是训练报表/仪表盘/数据大屏？
**结论：都不直接「训练」报表/仪表盘/大屏。核心是建设「语义层（数据集维度）」。**
- 报表/仪表盘/大屏本质是「数据集的视图」，智能问数应面向**数据集（底表/数据模型）**做 NL2SQL（Quick BI 即「向数据集提问」）。
- 但问数可**绑定作用域**：用户在特定报表/大屏内点「智能解读」时，自动带入该资产背后的数据集与筛选上下文（类似 Quick BI 仪表板解读）。
- 所谓「训练」在原型阶段 = 配置语义层（字段业务含义、术语同义词、指标口径、示例问数-SQL 对），作为 LLM 上下文；**不需要真实微调模型**。

### 2. 问数用什么统计策略、形成什么可视化图表？
- **意图分类**：查询类（聚合/排序/排名/对比/趋势/占比）vs 洞察类（归因/异常/预测）。
- **查询类 → NL2SQL**：自动拼装 维度(GROUP BY) + 指标(聚合) + 过滤(WHERE) + 时间窗口 + 排序。
- **洞察类**：维度下钻、指标归因、相关性分析（原型可用规则+LLM 简述，先不做的太重）。
- **图表自动选择**（关键映射）：
  | 用户意图 | 自动图表 |
  |---|---|
  | 趋势 / 随时间变化 | 折线图 |
  | 占比 / 构成 | 饼图 / 环形图 / 堆叠柱 |
  | 排名 / Top N / 对比 | 柱状图 / 条形图 |
  | 地区维度 | 地图 |
  | 相关性 | 散点图 |
  | 单一数值 / KPI | 指标卡 |
- 输出形态：**推理过程 + SQL + 图表 + 文字结论**（与竞品一致）。

### 3. 独立问数页面 / AI 问答中 / 切换解答助手与问数助手？
**结论：推荐「在 AI 助手中切换能力」方案（C）。**
- 复用现有 AI 助手对话面板、会话管理、反馈与记录机制，用户心智统一（"问 AI" 既能问功能也能问数）。
- 问数助手模式下，面板顶部增加「作用域选择器」（选数据集/某报表/某大屏）。
- 报表/大屏页面内保留「智能解读」快捷按钮，点击直接唤起问数助手并带入该资产上下文（无需手动选作用域）。
- 不推荐独立页面：割裂体验、重复造会话/反馈/记录能力。

### 4. 行业黑话 + 记录提问回答
- **行业黑话定义**：新增「语义层 / 术语词典」配置——
  - 同义词映射（"销量"→ sales_qty，"GMV"→ 成交额口径）
  - 指标口径定义（"毛利"= 收入−成本，单位、聚合方式）
  - 示例问数（标准问题 → 期望 SQL，用于 few-shot 提升准确率）
- **记录**：在现有「对话记录」基础上扩展一条 `type: 'query' | 'qa'`，问数记录额外存：生成 SQL、命中数据集、执行结果摘要、图表类型、是否命中语义层、反馈与修正 SQL。与「解答记录」共用列表与详情抽屉。

### 5. AI 独立子系统 vs 整合进左侧菜单（菜单权限控制）？
**结论：推荐「整合进左侧菜单 + 菜单权限控制」，但区分两端。**
- **用户端能力**（悬浮机器人：解答+问数+解读）= 全局组件，**不进菜单**，登录后所有页面可用（登录页除外，沿用现状）。
- **管理端能力**（AI 中心：知识库、模型、语义层、问数配置、记录）= 整合为左侧「AI 中心」一级菜单，子项由**菜单管理/权限**控制可见性（超管 / AI 管理员可见，普通用户不可见）。
- 复用现有「菜单管理 + 角色权限」机制，无需新建独立子系统与独立权限体系。

## 四、需要你确认的关键决策

1. **问数入口形态**：采纳「AI 助手内切换能力（解答/问数/解读）」？还是坚持独立问数页面？
2. **问数作用域**：默认面向「数据集」提问即可？是否要在报表/大屏页内做「智能解读」带入上下文（工作量更大）？
3. **语义层范围（原型阶段）**：先做「术语词典 + 指标口径 + 示例问数」即可？还是连「数据集字段业务含义自动导入」也做？
4. **图表策略**：采纳上面的「意图→图表」自动映射？是否允许用户在回答后手动切换图表类型？
5. **AI 管理归属**：采纳「整合进左侧菜单（AI 中心）+ 菜单权限」？还是希望 AI 完全独立成子系统？

> 确认后，按上述方案进入原型设计：扩展 AI 助手面板（能力切换 + 作用域选择）、新增「语义层/术语」配置页、扩展问数记录、AI 中心菜单整合。

## 五、已确认的关键决策（用户 2026-08-20）

### 新增文件
- `data/semanticLayer.ts`：语义层数据模型（TerminologyItem / MetricDefinition / ExampleQuery / DatasetSchema）+ 问数记录 `QueryLog` + 种子数据 + localStorage 存储 helper。

- `pages/QueryLogsPage.tsx`：问数记录（列表/筛选/详情抽屉/反馈统计）。

### 改造文件
- `components/AIAssistant/AIAssistantWidget.tsx`：新增「解答助手 / 问数助手」能力切换栏 + 问数模式作用域选择器 + 问数结果渲染 + 问数记录写入。

- `pages/AssistantAdminPage.tsx`：支持 `defaultTab` 属性（被 AI 中心子菜单复用）。

### 设计要点
- 问数引擎为原型模拟（规则 + 语义层），未真实微调模型；SQL 为 mock 生成，结果数据为模拟值。
- 问数记录与对话记录（解答）分离存储，分别由「问数记录」「对话记录」查看。
- 「智能解读」模式对报表/仪表盘/大屏返回核心指标摘要，不生成 SQL 取数。
